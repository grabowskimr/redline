# Output formats

The rendered batch is the actual product of this extension — it is what gets pasted into
a fresh Claude Code session. It must be unambiguous about *where* each change goes and
*what* is being asked for, and it must not waste tokens.

## 1. Rendering rules (all templates)

- Only notes with `included === true` and `done === false` are rendered.
- Group by file; files sorted alphabetically; notes within a file sorted by start line.
- Line numbers are **1-based** in output (editor-visible numbers), even though they're
  0-based internally. Off-by-one here is the single most likely bug — unit test it.
- Ranges render as `L142` when single-line, `L142-150` otherwise.
- Snippet fences get the language id from the document (`document.languageId`), falling
  back to the file extension, falling back to no language.
- Snippets longer than 40 lines are truncated with a `… (N more lines)` marker.
- Orphaned notes render in a trailing `## Unanchored notes` section with their stored
  snippet and a note that the line numbers may be stale.
- Body text is emitted verbatim. Do not reflow, do not escape — the user wrote markdown.
- Addenda append below the body separated by a blank line and `↳ ` prefix on the first line.

## 2. Template: `claude-prompt` (default)

Designed to be pasted as the first message in a Claude Code session.

````markdown
# Code review feedback

You're picking up review feedback on this repository. Below are {{count}} notes across
{{fileCount}} files, written while reading the code. Each note gives a file path, a line
range, and the code that was being looked at.

Please work through them in order. For each note: make the change, or if you disagree or
the note is ambiguous, say so and ask before proceeding. Where a note includes a
**Suggested change** block, treat it as the intended result, not necessarily literal text
to paste. Don't make unrelated changes.

**Repo:** {{repoName}} · **Branch:** {{branch}} · **HEAD:** {{sha}}{{#dirty}} (uncommitted changes present){{/dirty}}
**Breakdown:** {{kindCounts}}

---

## `src/comments/commentHost.ts`

### 1. 🐞 bug — L142-150

```ts
  const thread = controller.createCommentThread(uri, range, []);
  thread.comments = [comment];
  thread.collapsibleState = vscode.CommentThreadCollapsibleState.Expanded;

Recreating the thread here makes the widget flicker and lose focus when a note is edited.
Mutate the existing thread instead, and reassign `thread.comments` rather than pushing

**Suggested change:**

```ts
  const existing = this.threadsByNoteId.get(note.id);
  if (existing) {
    existing.comments = [new NoteComment(note.id, note)];
````

## 3. Template: `checklist`

For when the batch is a to-do list rather than a prompt.

```markdown
# Review notes — feat/pr-parity @ a1b2c3d — 2026-08-23

- [ ] **src/comments/commentHost.ts:142** (bug) — Recreating the thread makes the widget
      flicker; mutate in place and reassign `thread.comments`.
- [ ] **src/comments/commentHost.ts:203** (question) — Are disposed threads released, or
      leaked via the map?
- [ ] **src/store/reviewStore.ts:44** (nit) — Make `delete` consistently take an array.
```

No snippets, one line per note (wrapped at 100 chars), sorted by file then line.

## 4. Template: `json`

For piping into scripts or an agent that wants structure.

```json
{
  "generatedAt": "2026-08-23T14:02:11.482Z",
  "repo": { "name": "orca", "branch": "feat/pr-parity", "sha": "a1b2c3d", "dirty": true },
  "notes": [
    {
      "id": "0f2c…",
      "path": "src/comments/commentHost.ts",
      "startLine": 142,
      "endLine": 150,
      "kind": "bug",
      "body": "Recreating the thread here makes the widget flicker…",
      "suggestion": "const existing = this.threadsByNoteId.get(note.id);\n…",
      "snippet": "  const thread = controller.createCommentThread(uri, range, []);\n…",
      "language": "typescript"
    }
  ]
}
```

Line numbers here are **1-based** too, for consistency with what a human reads.

## 5. Template: `plain`

Body text only, grouped by file, no icons, no preamble — for pasting into a chat where the
context is already established.

```
src/comments/commentHost.ts:142
Recreating the thread here makes the widget flicker…

src/comments/commentHost.ts:203
Are disposed threads released, or leaked via the map?
```

## 6. Kind icons and ordering

| kind | icon | ThemeIcon | output weight |
|---|---|---|---|
| `bug` | 🐞 | `bug` | 1 |
| `security` | 🔒 | `shield` | 2 |
| `perf` | ⚡ | `dashboard` | 3 |
| `refactor` | 🔧 | `symbol-method` | 4 |
| `question` | 💭 | `question` | 5 |
| `todo` | 📌 | `checklist` | 6 |
| `comment` | 💬 | `comment` | 7 |
| `nit` | ✂️ | `lightbulb` | 8 |
| `praise` | ✨ | `heart` | 9 |

Weight is used only when `grouping === 'kind'`; default file grouping keeps document order
so the agent reads the file top-to-bottom.

## 7. Clipboard behaviour

- `vscode.env.clipboard.writeText(rendered)`.
- After a successful write, read it back with `clipboard.readText()` and compare — on some
  Linux/Wayland setups the write silently fails. If it mismatches, fall back to opening
  the rendered text in an untitled document and warn the user.
- Toast on success:
  `Copied 12 notes across 5 files to the clipboard.` with actions `Undo` and `Show batch`.
